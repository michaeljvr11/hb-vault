# Session 33 — LSM-4/5/6: Contact page and inquiries

**Date:** 2026-08-16 · **Cards:** [LSM-4](https://trello.com/c/Ah6EZCOW) / [LSM-5](https://trello.com/c/9y69dIul) / [LSM-6](https://trello.com/c/TkbgWKL2) · **Branch:** `feat/Ah6EZCOW-contact-page-and-inquiries` · **Status:** Open PR

- Shipped: LSM-5 `POST /inquiries` contact endpoint (public, throttled 5/60s per IP, persist-first with the Resend notify wrapped so a mail failure never loses a lead), with `ContactInquiry` entity, migration, native Postgres enum, DTO. LSM-4 `/contact` page (typed reactive form, `ContactService` wired to the API endpoint, native `<select>`/`<checkbox>`, WhatsApp CTA, failure-keeps-input, prerendered) — EmailJS and its three hardcoded keys dropped entirely. LSM-6 footer/nav links wired (Contact Support, About, Services, Register as Vendor), pre-existing Home active-state bug fixed, brand unified to "H&B E-Commerce" across nav/footer/auth/shells/title.
- Decisions: Bundled as one branch — LSM-4 consumes the contract LSM-5 defines, LSM-6 links the route LSM-4 creates. Contract written by the lead first so the two parallel agents could not race on it; LSM-5 ‖ LSM-4 in parallel on disjoint files, LSM-6 sequential last. Response SLA deliberately "within 1 business day" per `15-customer-support.md`, not hb-landing's "24–48 hours" — the migration source was wrong and the vault was right. `/services`' "The H&B Marketplace" heading kept: it names the marketplace **engine**, not the brand.
- Lessons: three of four review FAILs were **client/server disagreements at the seam**, not bugs inside either side — the form had no length caps while the DTO capped every field, and `Validators.email` accepts `jane@localhost` where class-validator's `@IsEmail` does not. Both would have surfaced as a server 400 rendered as a generic toast. Validation parity does not fall out of sharing types; it needs checking explicitly. Also: a `@Public()` write endpoint cannot trust the form (`@IsNotEmpty` + trim added), and WhatsApp's `#25d366` failed as a text background at 1.98:1 — the second brand-sourced colour in this feature to do so.
- Tests: `npm run lint:api` clean; `npm run test:api` **712/712** (52 suites); `npm run test -w @hb/web` **862/862**; `npm run build` clean, 3 routes prerendered. Page driven live against the dev server (validation blocks an empty submit, `maxlength` matches the API caps, nav active-state correct, no old brand string left in the DOM). **Not verified: the migration has not run against a live database and the form has not been POSTed end-to-end — the migration SQL was reviewed by reading only.**
- Follow-ups: admin read surface for `contact_inquiries` (a saved lead is invisible outside `psql` today), mobile nav parity for the marketing pages (`<768px` reaches them via footer only), `replyTo` on the inquiry notification email.
